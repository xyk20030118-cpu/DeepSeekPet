## ★ 第一次使用：先把角色包导入进去（重要）

从**轮次㉜** 起，APK 里**不再内置任何动作与表情**（APK 只有 37.5 MB）——
桌宠长什么样、会做什么，**全部来自角色包**。所以：

1. 安装本包里的 APK；
2. ★★ **轮次60 起交付物是分开的四件**（见下面「交付清单」）——把**另外下载的**
   `DeepSeekPet_默认角色包_v8.0.zip` 放到手机里（文件管理器能选到即可）；
3. 打开 App → 底部导航「形象」→ 点最上面那一行「**🎭 角色：… ›**」→ 选「**📥 添加角色包（.zip）…**」→ 选中它；
4. 导入完成后桌宠立刻换成这个角色（**106 个动作 + 27 张对话表情**，表情会跟着聊天气泡出现）。

> **交付清单（4 件，各自独立下载 —— 用户要求「角色包跟交付包还有语音模型分开发」）**：
>
> | # | 文件 | 大小 | 作用 |
> |---|---|---|---|
> | ① | `DeepSeekPet_v8.0_开发版.zip` | ~17 MB | **APK + 文档五件套**（自用/调试版） |
> | ② | `DeepSeekPet_v8.0_正式版.zip` | ~18 MB | **APK + 文档五件套**（正式签名版） |
> | ③ | `DeepSeekPet_默认角色包_v8.0.zip` | 312.9 MB | **动作与表情**（第 2 步要导入它） |
> | ④ | `DeepSeekPet_语音模型_8.0_sensevoice.int8.onnx` | 228.2 MB | **离线语音识别**（可选） |
>
> ★ **为什么要分开**：以前三样捆在一个 476 MB 的 zip 里，**改一行代码就要你重下 476 MB**；
> 现在只有 ①② 随版本变（十几 MB），③④ 基本不动，你可以只下需要的那件。
> ★ ③ 与 ④ **不进 APK**：不导入 ③ 就只有 1 个兜底待机动作；不导入 ④ 就没有离线语音（不影响其他功能）。

> **不导入会怎样**：App 能启动、设置页都能用，但桌宠只会播 APK 里那**1 个兜底待机动作**，也不会配图。
>
> **想做自己的角色**：同一行里「**➕ 新增角色**」→ 给它「**➕ 添加动作（从相册多选）**」、
> 在「**🎨 形象**」里换脸 → 最后「**📤 导出当前角色（.zip）**」就是一个能发给别人的角色包。
> 角色包格式见同目录的 `角色包格式.md`。

## 一、这个包是什么

**完整可编译的源码工程**（指「项目移植包」；开发版/正式版那两个 zip 里是 APK + 文档 + 语音模型 + 角色包），
不是只读快照。解压后可直接构建出与正式版同源的 APK。

正式发布版（`com.doropet.release`）由本工程通过 `build/make_variant.py` 自动生成，
两个版本共享同一份源码，**不要分别手改**，改完源码重新生成正式版即可。

> ### ⚠️ 安全提醒
> **发布出来的仓库里没有这把密钥**（口令也不公开）。自己构建正式版时请另行生成。
> 原工程内部文档里曾把口令写在明面上，这在「自己一个人用」时没问题，
> 但意味着**任何拿到这个 zip 的人都能签出与你完全同签名的包**。

>     -keyalg RSA -keysize 4096 -validity 10950 \
>     -storepass <你的新口令> -keypass <你的新口令> \
>     -dname "CN=<你的名字>, OU=DeepSeekPet, O=<你的名字>, C=CN"

>   所以第一次生成就要想清楚。

## 四、构建

构建分**两个阶段**，工具链跨两个环境，必须分开跑。

### 阶段① — Android 环境

用 **Eta Root Shell（Android 环境）** 执行，因为 `aapt2` 是 Android 原生程序。

```bash
cd /sdcard/DeepSeekPet_v8.0_完整工程
sh build/1_compile_android.sh
```

产物：`build/out/resbase.apk`（已编译的资源与 manifest）

> 共享存储是 `noexec` 的，脚本会把 toolchain 暂存到 `/data/local/tmp/dsp_build/` 再跑。

### 阶段② — Linux 环境

用 **Eta Linux 工具环境** 执行，因为需要 JVM。

```bash
cd /sdcard/DeepSeekPet_v8.0_完整工程
sh build/2_build_linux.sh
```

产物：`dist/DeepSeekPet_v8.0_rebuilt.apk`（开发版，debug 签名）

> Linux 环境如果报 `LINUX_ENVIRONMENT_NOT_READY`，
> 先到 Eta 设置里安装 Linux 工具环境。Alpine 会被重置导致 JVM 丢失，
> 重跑 `apk add --no-cache openjdk17-jdk` 即可。

### 生成并构建正式版

```bash
# 先在 Linux 环境生成正式版工程副本
python3 build/make_variant.py /sdcard/DeepSeekPet_v8.0_完整工程 \
                              /sdcard/DeepSeekPet_Release release

# 再在 Android 环境
cd /sdcard/DeepSeekPet_Release && DSP_VARIANT=release sh build/1_compile_android.sh
# 再在 Linux 环境
cd /sdcard/DeepSeekPet_Release && DSP_VARIANT=release sh build/2_build_linux.sh
```

> ### ⚠️ 最容易踩的坑
> **正式版两个阶段都必须带 `DSP_VARIANT=release`**，否则会静默走 dev 分支，
> 输出 `_rebuilt.apk` 并用 **debug 密钥签名**——装上去名字是「DeepSeek桌宠·正式版」，
> 但签名是调试签名，看起来完全正常，实际上是错的。
> 构建完务必核对日志里的 `Signer #1 certificate DN` 是否为 `CN=曦城那年`。

## 五、安装

```bash
# 开发版
adb install -r -d dist/DeepSeekPet_v8.0_rebuilt.apk

# 正式版
adb install -r -d /sdcard/DeepSeekPet_Release/dist/DeepSeekPet_v8.0_release.apk
```

共享存储 `noexec`，直接 `pm install /sdcard/...` 会失败，需先复制：

```bash
cp dist/*.apk /data/local/tmp/ && pm install -r -d /data/local/tmp/xxx.apk
```

两个版本包名不同（`com.deepseek.pet` / `com.doropet.release`），
**可以同时安装**，互不覆盖、数据独立。

## 六、已知的构建坑位

1. **dex 合并**：必须合并 `deps/sherpa-classes.jar` + `deps/kotlin-stdlib-1.9.0.jar`，
   并删掉 `META-INF`，否则安装成功但一启动就 `NoClassDefFoundError`。
2. **aapt2 link** 必须带 `--auto-add-overlay`。
3. **class 清单要写绝对路径**。
4. **BusyBox grep 不支持 `--include`**，Android 侧搜文件用 `grep -rn "pat" src/`。
5. 正式版下阶段①会打印
   `ls: .../com/deepseek/pet/R.java: No such file`——
   脚本里写死的开发版提示语，实际产物在 `out_release/gen/com/doropet/release/R.java`，
   **不是错误**。
6. 手工拼接改 Java 极易产生重复声明（同一声明两次、`setContentView` 丢失）。
   改完必须 `grep -c` 查重复声明 + 检查括号平衡，最后靠 `2_build_linux.sh` 的 javac 兜底。
7. 验证文案是否真进 APK：
   `unzip -p x.apk classes.dex > /tmp/x.dex && grep -aq "中文串" /tmp/x.dex`

## 七、v8.0 之后新增的用户可见功能（v8.0 现状）

> 这一节补的是 v8.0 之后陆续加进来、前面几节还没写的东西。每条都写了「怎么点进去」。

### 1. 自定义对话服务商 / API 地址（「陪伴 → 对话与人格」）

- 预置 **DeepSeek 官方 / Kimi / 硅基流动 / 智谱 GLM / 阿里云百炼 / OpenAI**；
  选定后 App 会**一起切换地址与默认模型**（避免"选了 A 但地址还是 B"这种错配）。
- 也能选「**自定义（OpenAI 兼容地址）**」接你自己的网关（LM Studio / one-api / vLLM…）。
  **明文 `http://` 已放行** —— 局域网与本机网关基本都是 http，而 Android 9 起系统默认会拦，
  本工程已解开（否则你填了**完全正确**的局域网地址也只会拿到 `CLEARTEXT … not permitted`）。
- ★★ **最容易踩的坑**：`127.0.0.1` 在**手机/模拟器上指的是设备自己**，不是你的电脑 ——

  | 你的场景 | 该填什么 |
  |---|---|
  | 模拟器连你电脑上的服务 | `http://10.0.2.2:端口/v1` |
  | 手机连你电脑上的服务（同一 Wi-Fi） | 电脑的**局域网 IP**，如 `http://192.168.1.5:7863/v1`，且服务要监听 `0.0.0.0` |
  | 真机用 USB 连着电脑 | 电脑上先 `adb reverse tcp:7863 tcp:7863`，这时 `127.0.0.1` 才真的通 |

  - 填了回环地址 App 会**当面提醒**（「⚠ 这个地址可能连不上」+ 上面这几条出路），
    设置页地址那一行也会被动带 `⚠ 可能是设备自己`。
- **🧪 测试连接**：一次 `/models` 往返，把**地址 / HTTP 状态码 / 服务端 message / 异常原文**
  原样显示出来 —— 通不通、几个模型、什么错，一眼看清（取模型列表失败时也会把真因带出来，
  不再只说"可能是网络问题"）。
- Key **按服务商分槽**保存（切服务商自动用该家已存的 Key，不必重填）；不填也能用（纯本地模式）。

### 2. 玻璃态自定义配色 + UI 透明度（「形象 → 主题与显示」，**仅玻璃态**）

- **🎨 自定义界面颜色…**：主色调 / 背景底色（**24 格调色卡**点一下即选，＋色相/饱和度/明度
  三段滑块自己调任意色，也能手动填 HEX）；**文字颜色** 自动/强制深/强制浅；
  **从背景图取色**（拿你当前背景图算出的四个候选色直接搭配）；**实时预览卡**；
  **导出 / 导入配色方案**（`.json`，可分享给别人，导入有校验闸）。
- **🫧 UI 透明度…**：背景底色 / 卡片面 / 弹窗浮层三项，各带安全下限（避免文字层级塌掉）。
- **✨ Mesh 光斑**：浓度（关/淡/标准/浓）、扩散（收紧/标准/扩散）、颜色（内置 / **跟随主色**）。
- **🩺 配色体检**：设置页那一行直接显示读数（如 `6.1:1 ✓`），点开逐条列出
  正文 / 次级 / 三级提示 / 小字强调 / 主色 / 危险色的真实对比度，不达标时给**可操作**建议。
  ★ 量的口径是**最坏的那一处**（文字落在"卡片叠光斑极值"上），照 WCAG AA —— 所以卡片调透、
  光斑调浓，读数都会跟着变，不会给你一个偏乐观的假绿。
- **明暗各存一套**（同一组颜色在深色/浅色底下要的不一样）。

### 3. 点击音效（「形象 → 表情与素材」）

- 戳桌宠（单击头 / 身 / 尾）响一声；**默认开**。
- 音色 **啵 / 哒 / 叮** 三档、音量 **轻 / 中 / 响** 三档，**改一档就当场试听**（不用退出去戳）。
- 音效由 App **现场合成**：不占素材、不用下载、无版权问题；设备没有音频输出或被别家独占时
  **静默跳过**，不影响其他功能。

### 4. ★ 本地模型：本机跑 GGUF 小模型（轮次62~64：引擎 + 导入 + 对话接线，**已经能用它纯本机对话**）

- **引擎**已进 APK（轮次62 第一轮）：交叉编译的 llama.cpp（arm64-v8a）+ 一层 JNI 包装，
  Java 侧入口是 `LocalLlm`。**APK 里不含任何模型文件**（+7.04 MB 全是推理库）。
- **导入入口**（轮次63 第二轮）：设置页「陪伴 → 对话与人格」最底下多了一组
  **「🤖 本地模型（手机本机跑，不联网）›」**，点开是操作面：
  - **📥 导入 .gguf 文件…** —— 用系统文件选择器挑一个 `.gguf`（0.5B~3B 的量化版，
    常见 0.4~2 GB）。App **先看文件头**：前 4 字节不是 `GGUF` 就**当场拒绝**，
    不会把一个压缩包/视频当成模型收下；然后**流式**拷进 App 私有目录
    `filesDir/models/`（**横向进度条 + 可取消**，拷贝过程不会把整个文件读进内存）。
  - **🔄 切换当前模型（已导入 N 个）…** —— 可以同时放好几个，但只有一个"当前"，
    列表里当前那个打勾。
  - **🗑 删除本地模型（当前那个）…** —— 确认框会写清**删的是哪个文件、多大**，
    以及"它正是当前使用的模型，删完要重新导入"。
  - 面板上还会报"引擎能不能用 / 已导入几个 / 共占多少 / 本机可用空间"，
    以及"内存里载没载入这个模型"。
- ★ 模型**不随包发**：得你自己挑一个 `.gguf`（我们不发模型文件，几百 MB 不该塞进安装包）。
  文件名会自动净化（去掉路径/非法字符/前导点、中文长名字按字符截断），
  同名会先问要不要覆盖（覆盖失败也保留原来那个）。
- **对话接线**（轮次64 第三轮 · 本版新增）：设置页「陪伴 → 对话与人格 → 🌐 服务商」里
  多了一项 **「本地模型（手机本机跑，不联网）」**。选了它之后：
  - 桌宠的对话**全部**走手机上那个小模型 —— 聊天窗口、悬浮窗「问一句」、启动问候、
    继续上次话题、戳/拖的反应、主动搭话、整点报时、场景搭话；
  - ★★ **一个 HTTP 请求都不发**：本地后端连"联网检索"都自动关掉（判据统一走
    `ChatRouter.webAllowed`），**不需要 API Key**，也不产生任何用量/费用
    （本地对话**不会**记账到"今日用量"里）；
  - **加载策略**：第一次用到它时才把模型载入内存（几百 MB，几秒到十几秒，
    **界面上有明确的等待提示**），之后**常驻**；只有换模型 / 删模型 / 切回在线才卸载；
  - **逐字出话**：本地这条链是**流式**的 —— 聊天窗口的"正在思考…"会边生成边变成正文，
    悬浮窗气泡也会一段一段往外冒（在线那条链是 `stream:false`，一次给整段）；
  - **没导入模型时不会静默失败**：会明确告诉你去「🤖 本地模型」点「📥 导入 .gguf 文件…」，
    并**如实说明代价**：「本机小模型慢一些、也更笨（几百 MB vs 云端几千亿参数），
    复杂问题建议切回在线服务商」。
- ★★ **它只有 arm64-v8a**：模拟器是 x86_64，装了也起不来 ⇒ 本功能只能**真机验**
  （离线断言做得再细，也替代不了"真机上到底出不出话、多少 tok/s、占多少内存"）。

### 6. ★★ 轮次66「提速」：GPU 默认开、不支持时自动回退 CPU（**请照这一段理解现在的行为**）

**用户要求**：「速度慢的离谱 用gpu加速」⇒ 这一轮加了 **Vulkan（GPU）后端**，
并且按你的口径做成 **默认开** —— **不需要你去哪个设置里手动打开**。

**你会看到什么**

* 设置 →「陪伴 → 对话与人格 → 🤖 本地模型」里面多了一行
  **「⚡ GPU 加速」**（现在是**开 / 关**两档，**默认开**），以及一行状态说明。
  ★ **默认就是开**；关掉是留给"某些机型 GPU 反而更慢/更烫"的退路，
  文案里写清了「关掉会慢很多」。
* 开关改完会**把内存里的模型放掉**，下一次对话按新设置重新载入
  （这是必须的：GPU 层数是**载入时**一次性给的，不放掉就是"改了没效果"）。
* **不支持 GPU 的机器不会被坑**：App 载入模型时会先问一句"这台机到底有没有可用的 GPU"，
  一个都没有就**自动走纯 CPU** 并记一行日志（`DSPLlm ★★ 后端设备：… ⇒ 一个 GPU 设备都没有，自动回退 CPU`）。
  **不弹报错、不拒绝加载、不会闪退。**
  就算 Vulkan 初始化成功、后来又失败，也会**自动卸掉重载成纯 CPU、并把这一次生成重跑一遍**。

**★ 实测到什么程度（诚实说）**

* 我们在一台真机上实测过（**只有这一台**）：
  **小米 2210132C（Xiaomi 13 / 骁龙 8 Gen 2 / Adreno 740）**，模型 **Qwen2.5-1.5B-Instruct Q4_K_M（1.0 GB）**。
* **好消息**：首字（prefill）**快了约一倍**（12.7 → 25.2 tok/s），首字等待 13.4 s → 7.8 s。
* **没做到**：★ **这台机器上 GPU 最终没被用上** —— Vulkan 的确认出了设备、也把 29/29 层都放上去了，
  但**驱动拒绝创建计算管线**（`vk::Device::createComputePipeline: ErrorUnknown`），
  于是走了上面那条**自动回退纯 CPU** 的路（所以没有闪退）。
  推测是我们的着色器编译器（NDK 自带的那一版）偏老；**这条路没修好**。
* **也没做到**：**吐字（decode）速度基本没变**（约 6.5 秒/字）—— 也就是你最初说的"慢的离谱"，
  **这一轮没有治好**。已经查到它**不是**指令集、不是线程数、不是磁盘读，
  更像是"每吐一个字都要把 1 GB 权重重新捞一遍、而捞得极慢"，下一轮从这里继续。
* **联发科（Mali）一台设备都没有验过**；除 1.5B 之外的模型也没有测过。
* 体积代价：为了带上 Vulkan，APK 从 **37.5 MB 涨到 56.6 MB**。

### 7. ★★ 轮次67「攻 decode 瓶颈」：GPU 那条路换了个修法 + 新增一行内存提示（**请看这一段**）

**这一轮做了三件事，其中一件是"推翻上一轮的判断"，两件是"以前拿不到的证据现在拿得到了"。**

**(1) ★★★ 「着色器编译器太老」这个假设被实测推翻了（省下你一个下午）**

轮次66 猜的是"NDK 自带的着色器编译器（glslc）太老，所以 Adreno 驱动拒绝我们的计算管线"，
于是想装新版 Vulkan SDK。**这一轮做了对照实验**：
用 **NDK r29 自带的新 glslc** 把 Vulkan 后端整个重编一遍，再和旧的逐字节比：

> **1119 个着色器、总共 25,354,464 字节，两次完全一样**；
> 抽查 `mul_mat_vec_q4_k_f32_f32` 等几个关键着色器，**SHA-256 完全相同**。

⇒ **换编译器这条路不可能改变结果**，别再花时间（顺带实测：Vulkan SDK 官方地址在本机
挂了约 2 小时只下到 2.9 MB，**这条路本来也走不通**）。

**(2) ★★ 换了一个**有上游依据**的修法：Adreno 的矩阵乘-向量着色器回退**

llama.cpp 上游已经有人在 Adreno 上踩过同一个坑（issue **#28635** / PR **#29165**），
PR 描述里**逐字**写着「**q4_K at 1 column fails pipeline creation with VK_ERROR_UNKNOWN**」——
而"1 列"就是**单字解码**。修法是让这类着色器改走**共享内存**归约、不用子组归约。
本工程把它做成**只按厂商判断**（Qualcomm）的默认回退，并**留了一个对照开关**，
这样同一台手机上"改之前 / 改之后"能直接比。

> ★★★ **诚实说**：这条修法**有上游依据，但到本轮结束时仍然没能在真机上确认它治好了** ——
> 交付的这一版里它**已经编进去了、默认生效、对照开关也在**，
> 但"Adreno 740 上确实不再报 ErrorUnknown 了"这句话**我们没说**。
> 你在设置里的「⚡ GPU 加速」保持**开**即可；★ 如果这台机器的 GPU 真的用不了，
> 现在会**明确报错**（不再偷偷回落 CPU）并给你一颗一键改成「关」的按钮 ——
> **不会闪退**，也不会让你以为在用 GPU 其实在慢慢用 CPU。
> （★ 这一条的行为在**轮次69** 又改了一次，见下面第 8 节。）

**(3) ★★ 以后能看见"到底卡在哪"了（这一轮把证据链补齐）**

* **每一个字 6.5 秒**这件事以前只有间接推断；这一轮补上了三条**直接**读数：
  页面错误计数（修好了一个一直返回 -1 的解析 bug）、
  **模型文件真正常驻内存多少**（`RssFile`）、以及被换出去多少（`VmSwap`）。
* 打开模型时还会**主动预热**（`fadvise`）并**尝试把它锁在内存里**（`mlock`）——
  成功/失败都会记一行日志（Android 给普通 App 的锁内存配额很小，失败是预期结果）。
* ★ **设置页新增一行**：当**模型明显偏大 / 当前可用内存比模型还小**时会多出一行
  **「🧠 内存提示：…」**，把"模型多大 / 本机内存多大 / 当前可用多少"和
  **真机实测的 6.5 秒/字**一起摆出来，并直接建议换 0.5B。
  ★ 模型放得下时**这一行不会出现**（不塞"没问题"这种噪声）。

**★ 本轮结束时仍然没做到的（照实说）**

* **还不知道那条 Adreno 回退在真机上有没有生效**（见 (2)）—— 这是本轮最大的未完成项；

### 8. ★★★ 轮次69「开 / 关 GPU」：修好"换了模型也没用"，并新增「⏏ 卸载模型」（**请看这一段**）

**用户要求**：「**增加模型卸载功能，现在安装了之后模型无法更换其他的gguf模型，
然后吧加速做成开GPU**」。这一轮是**修 bug + 简化设置**，不是加新功能。

**(1) ★★★ 先说清"换不了模型"到底坏在哪（查出来的真 bug，不是界面问题）**

上一版（轮次68）把 GPU 加速做成三态、默认「强制」，并在**原生层**加了一个进程级的
"以前失败过就再也不许试"的标记：只要 GPU 失败过**一次**，之后**每一次加载**
（换模型、重新导入、甚至同一个模型再来一次）都会**直接失败**，
只有"用户手动去改一次 GPU 方式"才能把它清掉。

而上一版默认就是「强制」、真机上 Vulkan 的计算管线又被 Adreno 驱动拒绝
⇒ 用户**必然**会撞上那一次失败 ⇒ **换任何一个 gguf 都只会得到同一句报错**。
**界面上的表现就是"模型无法更换"。** 这就是你报的那个问题。

⇒ 修法：把那个标记**整个删掉**。现在每一次加载都是一次**全新的尝试**，
失败就如实报、成功就用 —— 卸载 / 更换 / 删除 / 重新导入 / 切回在线，五条退路全都通了。
（"不重复白等一次"这点收益，不值得用它换掉"换不了模型"。）

**(2) 「⚡ GPU 加速」收回**两态**：开（默认）/ 关**

| 档位 | 行为 | 失败时 |
|---|---|---|

### 10. ★★★ 轮次71「继续做 GPU 加速」：把"只能在电脑上做的 A/B"搬进手机 + 一颗自检按钮（**请看这一段**）

前几轮一直卡在同一句话上：**这台手机的 GPU 到底行不行、哪个参数有用，没有真机读数**

**① 新增「🧪 本地推理自检」**（设置 →「陪伴 → 对话与人格 → 🤖 本地模型」）

* 那一屏里有：`结果=成功/失败`、`GPU 档位=`、`是否有 Vulkan GPU 设备=`（**名字**也在里面）、

* **后台跑、有进度、随时能取消**（放主线程就会 ANR）；跑之前会先放掉内存里的模型
  —— 这样用的才是你**当前**的设置（GPU 层数与调优旋钮都只在载入时给一次）。

**② 新增「🎛 本地推理调优（进阶 · A/B 用）」**（同一个面板再往下）

**八个小旋钮**，每个都有默认值 —— **什么都不动 = 和上一版完全一样**（不玩 A/B 的人零影响）：

| n_ubatch（物理批大小） | 128 / 256 / 512 / 1024 | 512 | **有上游依据**：`llama_context_params.n_ubatch` |

### 11. ★★★ 轮次72「真机 GPU 实测」：这台机器的结论出来了 —— **建议用「关」（纯 CPU）**（**请看这一段**）

**这一轮用户把手机连上了电脑** —— 这是本工程**第一次拿到真机读数**
（之前每一轮都写着"开发机 `adb devices` 全程为空"）。原始读数在工程 `build/_r72/` 下。

**测的是哪台机器**（★ 读数**按机型分段记**，两台机器的数字不许混）：

| 项 | 值 |
|---|---|
| 型号 / product | **25091RP04C** / `piano` |
| SoC / GPU | **骁龙 8 Elite（SM8750P）** / **Adreno (TM) 830**（驱动 `V@0800.72`） |
| 内存 / 系统 | 12 GB / Android 16（HyperOS `OS3.0.307.0.WPYCNM`） |

**7 组 A/B**（同一台机器、同一个模型 `qwen2.5-1.5b-instruct-q4_k_m.gguf`、同一条固定提示、贪心）：

| 档位 | 结果 |
|---|---|
| GPU 开（默认档，含轮次67 那条 Adreno 补丁） | ❌ `compute pipeline creation failed for mul_mat_vec_q4_k_f32_f32: ErrorUnknown` |
| 强制 subgroup（对照组）/ MMVQ 关 / MMVQ 强制 / 算子融合关 / 异步提交关（共 6 组） | ❌ **全部失败，报错逐字相同** |

**三条结论（实测，不是推测）**：

1. ★★★ **GPU（Vulkan）在这台 Adreno 830 上用不了**：设备认得出来、29 层也真的卸载上去了
   （日志里是 `load_tensors: offloaded 29/29 layers to GPU`），但驱动在**第一次建计算管线**时拒绝。
   ★ 轮次67 那条 Adreno 补丁在这台机器上**也没治好**（开关它走的是两条不同的着色器路径，
   **两条都失败**）。⇒ **别再猜参数了。**
2. ★★★ **"慢得离谱"不是内存问题**：模型 1.0 GB，`RssFile` 实测 **1214 MB**（= 权重**常驻内存**），
   被换出只有 23 MB。手册里那个"**6.5 秒/字 / 163 MB/s**"是**另一台 8 GB 手机**上的读数，
   **不适用这台**。
3. ★★★ ⇒ **在这台机器上，最佳设置就是「⚡ GPU 加速 → 关（纯 CPU）」**：
   decode **22 ms/token（44.75 tok/s）**，比那台 8 GB 机的 6.5 秒/字快约 **300 倍**。
   ★★ **注意**：App 的**默认档仍然是「开」**（那是用户点名要的默认）；
   「关」是**这台机器实测之后的建议**，不是全世界的默认。
   ★ 收尾时又复现了一遍：**44.84 tok/s（22 ms/token）** ⇒ 量级可重复。

**这一轮顺手修掉的三个缺陷（都是真机上才看得见的）**：

* ★★★ **本地模型面板原来不能滚** ⇒ 在这台机器上它把最后几行
  （切换 / 删除 / 卸载 / ⚡ GPU 档位 / 🧪 自检 / 🎛 调优）**裁到屏幕外**，
  **你根本点不到「🎛 本地推理调优」**（实测 a11y 树里连这个文字节点都不存在）。
  现在面板可以上下滚，那几行都够得着了。
* ★★ **自检报告里原来会印 `-1 ms`**（"这一步没跑到"的哨兵被当成数字印了出来）⇒
  现在写 **`未测到（这一步没跑到）`**，而且那一行**不会再带 `0.00 tok/s`**
  （`0.00 tok/s` 会被读成"跑了但极慢"，而事实是**根本没跑**）。
* ★★★ **自检的结论原来会撒谎**：它只按"有没有认出 GPU 设备"判 ⇒ 纯 CPU 跑得很快时

**没测到的（老实说，免得把"某一档能跑"当成"GPU 全面可用"）**：
`flash attention` / `n_ubatch` / `mlock` / `载入方式` 这四个**只在载入时生效**的旋钮
**没有**在 GPU 那条路上试（理论上救不了被拒的管线，但那是**推断**）；

### 12. ★★★ 轮次73「把最后一条着色器也试了」：**三条归约变体全失败**（**请看这一段**）

轮次72 之后还剩一个**没人试过**的格子：q4_K 的矩阵乘有三条着色器变体

| 档位 | 结果 | 现场证据 |
|---|---|---|
| 全默认（GPU 开） | ❌ | `compute pipeline creation failed for mul_mat_vec_q4_k_f32_f32` |

### 13. ★★★ 轮次74「自动硬件计划」：**你什么都不用调**（**请看这一段**）

你这一轮的原话就是需求：**「运行时自动检测硬件 → 动态计算 -(n-gpu-layers)
→ 自动降级兜底不用用户手动调参数。」**

**所以默认档从「开」改成了「自动」**：设置 → 陪伴 → 对话与人格 → 🤖 本地模型 →
「⚡ GPU 加速」现在有三档，默认是 **`⚡ GPU 加速：自动（按硬件决定）`**。

它每次载入前做三步（全自动）：

1. **看硬件**：枚举 GPU 设备（名字 / 显存）+ 当前可用内存 + 从 GGUF 头读**层数**；
2. **算层数**：`每层 = 模型体积 / 层数`；`预算 = 可用内存 × 55%（上限 3072 MB）`；
   `n_gpu_layers = 预算 / 每层`。放得下全部 ⇒ 全放；≥1/3 ⇒ 部分放；再少 ⇒ 纯 CPU；
   **已知坏机型（Adreno 830，前两轮实测）⇒ 直接纯 CPU**，不再白试一次；
3. **自动降级**：计划用 GPU、但载入或第一次生成因为 GPU 原因失败 ⇒ **自动卸掉、
   按纯 CPU 重载重跑一次**，并把原因记下来。

★★ **这不是"偷偷回落"**（那正是轮次69 删掉的东西）：面板会显示
`自动：Adreno (TM) 830 → 纯 CPU（原因…）`，日志有 `★ 自动降级：…`，
自检报告有 `自动计划=… / 硬件=… / 自动降级=是`。你随时能看见它决定了什么。
★ 「开 / 关」保留为**手动覆盖**：「开」是"只走 GPU、失败不回落"的对照档（给要做 A/B 的人）。

★ 诚实边界：已知坏机型名单**只有 Adreno 830**（实测）；别的机型会**先试** GPU、
失败再降级 —— 这条路径**没有真机读数**（本轮设备反复掉线，自动档的真机验收没跑成）。
层数读不到时会按 32 层**估算**（报告里会标"估算"），不是装成读到了。

## 八、工作模式（v8.0）诚实边界

> 这一节只讲**工作模式**这条线，和上面「七」「九」讲的本地模型功能是两回事。

**本轮修的一处用户报障（轮次139）：端口不固定 ⇒ 每次都要重新配置模型**

- **机理（已从上游前端字节码核实）**：网页的配置存在浏览器的 `localStorage` 里，
  而 `localStorage` 按「协议+域名+**端口**」隔离 ⇒ 宿主端口一旦漂移（旧逻辑会 3080→3090→内核随机），
  新地址上的 `localStorage` 是空的，用户配好的模型/API Key 就整片消失。
- **端口为什么会漂**：旧逻辑是「上次端口 → 3080 → 3090..3095 → 内核分配」，3080 被残留进程占着就往后跳（**现在固定 30800**，不再有任何降级）。
- **改法（不需要 root）**：端口**首选固定 30800**；被占先清残留进程（只杀本 App 名下进程）再试；
  仍清不掉才退到**保底端口 30801 并永久记住**（此后不再漂）。同时修好了"复用上次还在跑的宿主"
  这条路径（以前读错了配置格，永远命中不了）—— 复用比杀进程更好：端口不变，网页配置就不丢。
- **代价（如实写）**：如果之前你已经在别的端口上配过模型，升级后第一次到新端口仍需**再配一次**，
  之后永久保持。若 30800 被别的 App 长期占用，会退到 30801（同样记住），而不是反复跳。
- 断言：`verify_harness_client` 46 项、反向 16/16；`verify_dual_track` 81 项、反向 17/17；全量套件见下。
- ★★ **真机已经验到了**（2026-10-30 · <设备序列号> / PA2671 / Android 16）：
  - 新宿主确实监听 **30800**（`/proc/net/tcp` 里 `0x7850`），页面正常打开
  - 强制停止后再进：`复用已在跑的宿主：http://127.0.0.1:30801/…（HTTP 303，端口没变 ⇒ 网页配置还在）`
  - 30800 被**杀不掉的 root 孤儿**占死时：自动退到 **30801** 并成功打开页面（保底路径实测有效）
  - 重启后仍用 30801（**端口不漂**）
  - ★ 同一轮还抓到并修掉一个真 bug：App 侧枚举 `/proc` 因 Android **hidepid 看不到 root 进程**，
    "清残留"永远返回 0 个 ⇒ 这就是"宿主没打印 dsh web"的真相；root 清理改成整段在 `su` 里做。

**已经在真机上验证过**（arm64 · PA2671 / Android 16 / KernelSU root）：

- 宿主能起来并打印 `dsh web: http://127.0.0.1:3080/?token=…`（★ 这是**当时**的读数：那一版的端口还是上游默认 3080；本轮已固定为 30800，其余行为不变）
- 工作区在 `/sdcard/DeepSeekHarness`：访客内 `pwd` 确认、`touch` 写入 `WRITE-OK`
- `/sdcard` 与访客家目录 `storage/` 都能列出手机公共存储（Alarms/DCIM/Documents/Download…）
- 右上角 ⚙ 可拖动且坐标被记住（prefs `dsh_gear_x/y`）
- 会话保存早期的 `link()` EACCES 已修（改成 rename 回退）：实测 `link=FAIL` / `rename=OK`
- **需要手指点的交互，2026-10-27 用户已实测**：长按桌宠 →「进入工作模式」、⚙ 菜单（设置 / 退出）、
  退出二次确认、手机文件访问权限弹窗与「管理文件权限」跳转
  （`adb input swipe`/`motionevent` 在真机会被合成 tap，所以这几项只能人手指点验）
