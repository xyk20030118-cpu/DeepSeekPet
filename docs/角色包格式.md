# 角色包格式规范（v8.0）

> 一个「角色包」＝ **形象 + 动作 + 台词 + 表情 + 性格** 的打包格式。
> 用设置页「形象与动作 → 动作系统 → 导入角色包」导入即可整包生效；也能导出给别人用。
> 本文既是给作者的格式说明，也是导入器的校验依据（导入时逐条检查，不符合会明确报错）。
>
> ★ **最省事的做法（v8.0 起）**：连 `pack.json` 都不用写 —— 把动图打成 zip 丢进来，
> 导入器会按**文件名前缀**自动归场景（见本文第三节之 3.4）。手机上也行：
> 设置页「形象与动作 → 动作系统 → ➕ 添加动作」，从相册多选图片，选个场景即可。

---

## 一、目录结构（标准包）

```
我的角色.zip
├── character.json          角色元信息（名称/作者/版本/封面）—— 可选
├── anim/
│   ├── pack.json           ★ 动作系统：场景 → 动作（本文第三节）—— **可选**
│   ├── lines.json          动作 → 台词（可选）
│   └── clips/              ★ 动作素材（*.webp / *.gif / *.png / *.jpg，文件名即动作名）
│       ├── 待机呼吸休闲.webp
│       └── ...
├── memes/
│   ├── memes.json          表情包索引：名称 → 描述（可选）
│   └── *.png               表情图（可选）
├── appearance/             ★ 形象素材（**随包走**，本文第五节之一）—— 可选
│   ├── appearance.json     用哪一种形象来源
│   ├── image.png           上传的静态图 / anim.gif 动图 / model/ 序列帧包 / l2d/ Live2D 包
│   └── ...
└── persona.md              性格提示词（可选）
```

**极简包**：只放 `anim/clips/*` 就能导入（元信息用默认值，`pack.json` 由导入器自动生成）。
`anim/pack.json` 与 `character.json` 都**可以省**。

> ★ **素材不进 APK**：内置角色只带 1 个待机动作；完整 106 个动作在交付的
> `DeepSeekPet_默认角色包_v8.0.zip` 里 —— 它同时也是本文格式的**参考实现**
> （由 `build/pack_character.py` 生成）。

## 二、character.json

```json
{
  "id": "my_pet",
  "name": "我的小猫",
  "author": "你的名字",
  "version": "1.0",
  "note": "随便写点什么"
}
```

- `id`：可留空（导入时按 zip 文件名生成）。**只允许字母/数字/下划线/连字符**，会被用作目录名。
- 其余字段仅用于展示；缺省时用 `id` 当名称。

## 三、anim/pack.json（动作系统 2.0）

```json
{
  "version": 2,
  "scenes": {
    "idle":    { "clips": ["待机呼吸休闲"] },
    "drag":    { "clips": ["被拎起来挣扎", "被拎起来生气"] },
    "interact":{ "clips": ["蹭蹭你"] },
    "roam":    { "clips": ["小跑", "踱步"] }
  },
  "events": { "balance": [], "whisper": [], "workStatus": [] }
}
```

- **简写**：`"idle": ["动作名", ...]` 与 `"idle": {"clips": [...]}` 都可以。
- **带权重**：`"clips": [{"id": "吃Token", "weight": 3}]`（权重只在「随机池」参与抽取时有用）。
- 场景里写了名字、但 `clips/` 里没有对应文件 ⇒ 该场景**静默跳过**（导入时会列出"缺文件"清单）。

### 3.1 场景全表（**id 固定，由程序定义**；你只能决定每个场景挂哪些动作）

| 场景 id | 名字 | 什么时候会播 | 播放方式 |
|---|---|---|---|
| `idle` | 待机 | 没有任何操作时的默认循环 | 循环（默认只放 1 个＝永不随机换动作） |
| `click` | 点击 | 单击 / 戳一下桌宠 | 播一次 |
| `interact` | 互动 | 连续戳、亲近类互动反应 | 播一次 |
| `drag` | 拖拽 | 按住拖动**过程中** | 循环 |
| `roam` | 漫游 | 自动走动**过程中** | 循环 |
| `turn` | 转向 | 漫游换向 / 走到屏幕边回头 | 播一次 |
| `dock` | 贴边 | 吸附成屏幕边缘竖条时 | 播一次 |
| `pool` | 待机随机池 | **默认不播**；用户打开「待机时随机换动作」后才参与待机 | 循环 + 按权重抽 |
| `hour` | 整点报时 | 整点报时那一下 | 播一次 |
| `festival` | 节日/节气 | 命中节日或时段时 | 播一次 |
| `tap_head` | 点击头部 | 戳到头部 | 播一次 |
| `tap_body` | 点击身体 | 戳到身体 | 播一次 |
| `tap_tail` | 点击尾巴 | 戳到尾巴 | 播一次 |
| `double_tap` | 双击 | 双击桌宠（打开输入条） | 播一次 |
| `long_press` | 长按 | 长按桌宠（弹出功能菜单） | 播一次 |

### 3.2 事件场景（由事件触发，写在 `events` 里）

| 事件 id | 名字 | 触发时机 |
|---|---|---|
| `balance` | 余额事件 | **余额档位变化**时。数组顺序 = 档位从低到高：`<1 元 / 1~5 / 5~10 / 10~20 / 20~50 / ≥50`（缺位补空字符串） |
| `whisper` | 碎碎念 | 桌宠主动搭话时（纯本地档与 API 档都走） |
| `workStatus` | 工作状态 | 前台应用属于「工作／办公」时 |

### 3.3 默认角色包的归类（可作为填写参考）

```
idle 1 ｜ click 5 ｜ interact 7 ｜ drag 1 ｜ roam 3 ｜ turn 1 ｜ dock 1 ｜ hour 2
festival 21 ｜ tap_head 1 ｜ tap_body 1 ｜ tap_tail 1 ｜ double_tap 1 ｜ long_press 1
pool 44 ｜ events.balance 6 ｜ events.whisper 3 ｜ events.workStatus 6     合计 106
```

其中几处是**语义映射**，值得抄：
`dock` ← `原地重力下蹲压缩`（被压扁成竖条）、`tap_tail` ← `用鲸鱼尾巴拍打地面`、
`double_tap` ← `深度思考碎碎念`、`long_press` ← `是啊，吃什么`、
`hour` ← `轻快记录`/`悠闲哼歌`、`roam` ← `螃蟹走路`/`原地漂浮踏步`/`原地左转奔跑`。

### 3.4 ★ 不写 pack.json：用「文件名前缀」直接指定场景

`anim/pack.json` 没有时，导入器会**按文件名自动归类**（`ClipNaming.sceneOf`），规则三级：

1. **场景中文名的前缀，最长优先**：`待机-xxx` → `idle`、`点击-xxx` → `click`、
   `拖拽-xxx` → `drag`、`互动-xxx` → `interact`、`漫游-xxx` → `roam`、`转向-xxx` → `turn`、
   `贴边-xxx` → `dock`、`碎碎念-xxx` → `whisper`……
   （用的是第三节 3.1/3.2 表里的**名字**：最长优先是为了让 `点击头部-xxx` 归到 `tap_head`、
   `待机随机池-xxx` 归到 `pool`，而不是被 `点击` / `待机` 抢走。）
2. **简称（唯一才认）**：取文件名开头那段连续汉字，若它**恰好与一个**场景名相关
   （是它的前缀，或被它包含），就用那个场景 —— `整点-报时`→`hour`、`节日-春节`→`festival`、
   `余额-分文不剩`→`balance`、`工作-码字`→`workStatus`、`头-xxx`→`tap_head`、
   `身-xxx`→`tap_body`、`尾-xxx`→`tap_tail`（后三个对应「点击头部/身体/尾巴」，
   注意那几个名字的末字是「部/体/巴」，所以按"包含"认，不是按"结尾"认）。
   （"唯一才认"是故意的：`待` 同时出现在「待机」与「待机随机池」里，猜错不如不猜 ⇒ 落到 `pool`。）
3. 都不命中 ⇒ `pool`（待机随机池 / 动作库）。

另外两条：
- **`idle` 一定会有一个**：取文件名含「待机」的那个；一个都没有就取**第一个**文件
  （桌宠总要有个站着的动作）。
- 前缀命中的文件**只进它自己的场景**，不再重复进 `pool` —— 否则「待机时随机换动作」一开，
  点击/拖拽动画也会混进待机轮播。

归一化示例（zip 里就这 6 个文件，没有 `pack.json`）：

```
待机呼吸休闲.webp   点击-摸头.webp   拖拽-挣扎.gif
头-被戳到.png      整点-报时.webp   小猫咪.png
```
⇒ 自动生成：
`idle: [待机呼吸休闲]`、`click: [点击-摸头]`、`drag: [拖拽-挣扎]`、
`tap_head: [头-被戳到]`、`hour: [整点-报时]`、`pool: [小猫咪]`。

> 导入完成后，这份自动生成的 `anim/pack.json` 会**写进角色目录**
> —— 角色包从此自带配置，再导出/分享给别人也是完整的。

## 四、anim/clips/（动作素材）

| 项 | 要求 |
|---|---|
| 格式 | **animated WebP**（推荐，透明通道最好）或 **GIF**；**PNG / JPG 也可以** —— 按**静态动作**播（单帧，播一次的场景会按"播一次"的时长收尾） |
| 文件名 | = 动作名（可中文）。**不要**带路径、不要重名。★ 没有 `pack.json` 时文件名前缀还决定场景（见 3.4） |
| 尺寸 | 建议与内置素材同规格（约 500×556 级别，竖构图）；过大会明显增加内存与导入时间（超过 1024 像素会被等比缩到长边 1024 再解码） |
| 数量 | 建议 ≤ 120 个/包；单个 ≤ 8 MB。**硬上限（导入器会拒绝超限）**：单文件 ≤ 16 MB、动作数 ≤ 400、整包 ≤ 600 MB |
| 帧率/时长 | 短动作 2~4 秒最舒服（播一次的场景会按动画自身时长收尾） |
| 透明 | 建议真透明；带底色会在桌面上露出方块 |

## 五、其他可选文件

- **`anim/lines.json`**：`{"动作名": ["台词1", "台词2"]}` —— 该动作播放时随机说一句。
- **`memes/memes.json` + `memes/*.png`**：表情包（`{"名字": "描述"}`），
  用于「气泡里配上表情包图片」。**按角色隔离**（切角色 = 换一套表情）。
- **`persona.md`**：性格提示词（纯文本）。也是**按角色隔离**的。
- **`appearance/`**：形象素材（见下一节）。

---

## 五之一、appearance/（形象随包走）

**一句话**：`appearance/` 就是运行期那个「这个角色长什么样」的目录，**原样搬进包里** ——
导出时自动带上，导入时自动装回去。**有了它，你把角色包发给别人，对方看到的就是同一张脸**；
没有它，对方会用他自己上一次的形象（或内置形象）。

```
appearance/
├── appearance.json     {"version":1,"source":"image"}   ← 用哪一种来源
├── image.png           上传的静态图（png/jpg）
├── anim.gif            上传的动图（GIF / 动态 WebP）
├── model/              序列帧模型包（zip 解压后的目录）
└── l2d/                Live2D 模型包（meta.json + 分层 PNG）
```

- `source` 取值：`builtin`（内置角色包）/ `image` / `anim` / `model` / `custom_l2d`。
- 素材用**固定名**（`image.png` / `anim.gif` / `model/` / `l2d/`），重传即替换；
  四种素材**可以同时在**，`source` 决定现在用哪一种（设置页「🎨 形象来源」可随时切）。
- **素材缺失自动回退内置**（选了 `image` 但包里没有 `image.png` ⇒ 用内置形象，不会留一块空白）。
- **包没带 `appearance/`** ⇒ 导入时**不动**对方这个角色已有的形象
  （包没提形象，就不该改变现状）。
- ★ `appearance/` 里的图片**不会被当成动作**（导入器扫动作时跳过 `memes/` 与 `appearance/`
  这两个辅助目录），所以你的脸不会出现在动作库里。

> 手工做包时**可以完全不管** `appearance/`：不写就是"不带形象"。
> 想带上，最简单的办法是在 App 里设置好形象后用「📤 导出角色包」——
> 导出的包会自动把 `appearance/` 一起打进去（导出提示里会写"已带上形象素材"）。

## 六、导入时的校验（导入器逐条检查）

1. zip 能正常解压；条目名**不含绝对路径 / `..`**（防路径穿越）；
2. **至少要有一个动作文件**（`.webp` / `.gif` / `.png` / `.jpg` / `.jpeg`，任意目录，递归找）；
   `anim/pack.json` **可以没有** —— 没有就按文件名自动归场景并把生成的配置写进角色目录（见 3.4）；
3. 动作文件的扩展名必须是上面那五种之一（改扩展名的别的文件会解码失败 ⇒ 播不出来）；
4. 数量与体积不超过上面第四节的**硬上限**；
5. `pack.json` 引用但缺文件的动作会**列出来提示**（不阻断导入，缺的那个场景就是不播）；
6. `id` 冲突时：覆盖同名角色目录（导入前会问一次）。

★ 全树扫动作文件时会**跳过辅助目录 `memes/` 与 `appearance/`**（表情图、形象图也是 png，
混进来会变成"动作"，用户会在动作库里看到自己的表情包和脸）。判据在
`PackFormat.isAuxDir`（一份清单，加新辅助目录只改那里）。

★ 包里带 `appearance/` 时，导入会把它装进这个角色的**形象覆盖层**
（`filesDir/appearance/<角色 id>/`）⇒ 导入后**看到的就是导出者那张脸**；
包里没有 `appearance/` 时**不动**这个角色已有的形象。

导入完成后：自动切到该角色 → 重建悬浮窗 → 立刻生效（无需重启 App）。

## 七、兼容性

- **老格式（1.x）** 仍能直接用：`pet_anim.json` 里的
  `idle / turn / drag / clicks / moves / categories / events` 会被自动映射到新场景
  （`moves → roam`、`categories → pool`、`clicks → click`）—— 你以前做过的素材包不用改。
- 2.0 只多了一个 `scenes` 节点：有它就走新格式，没有就按 1.x 映射。

## 八、最小示例：只把「拖拽」换成自己的动画

```
我的角色.zip
├── anim/
│   ├── pack.json
│   └── clips/
│       ├── 被拎起来挣扎.webp
│       └── 被拎起来生气.webp
```

`anim/pack.json`：

```json
{ "version": 2, "scenes": { "drag": ["被拎起来挣扎", "被拎起来生气"] } }
```

导入后：其余场景保持**内置**（因为没写就回退到内置配置），只有拖拽换成你的两个动作。

★ 这个包里连 `anim/pack.json` 都可以不写：把两个文件直接叫
`拖拽-被拎起来挣扎.webp` / `拖拽-被拎起来生气.webp`，效果一样（见 3.4）。

## 九、不开电脑：在手机上往当前角色加动作

设置页「**形象与动作 → 动作系统 → ➕ 添加动作**」（动作库页里也有同一个入口）：

1. 从相册**多选**图片（动图或静态图都行，webp / gif / png / jpg）；
2. 选一个目标场景；也可以选「**只加入动作库（先不绑定）**」，之后再在场景页里绑；
3. 完成即生效（不用重启，也不用重新导入整包）。

另有一个更短的入口：**场景编辑器里点进某个场景 → 「📥 导入动画到此场景」** ——
多选图片后它们会被追加绑到**这个场景**（不会替换掉原有绑定，也不会抹掉你调好的权重），
适合「我在看这个场景，就想给它加两个动画」。

落地方式（作者可据此理解与手改的差别）：
- 文件被复制进**用户素材目录** `filesDir/scenes/<角色 id>/clips/`
  （与绑定覆盖文件**同处用户覆盖层**；内置角色与用户角色一视同仁 ——
  内置角色的素材在 APK 里、只读，没必要为它造一个假角色目录）；
- 素材层按角色查这个目录，**优先级高于角色包**（同名以用户加的为准）；
- 绑定写在覆盖层 `filesDir/scenes/<角色 id>.json` 里 ——
  角色包的 `anim/pack.json` **一个字节都不会被改**，所以随时能「恢复角色包默认」；
- 重名一律加序号（`名字_2`、`名字_3`），重名判断会**并上角色包与当前有效配置里的动作名**，
  绝不会静默盖掉角色包里的同名动作；
- 想撤销全部自定义：删掉 `filesDir/scenes/<角色 id>`（目录 + 同名 `.json`）即可。

## 十、导出：按**当前绑定**打包的自洽包

设置页「形象与动作 → 动作系统 → 📤 导出当前角色」导出的 zip **不是**角色目录的复制，
而是**按你当前的绑定现场生成**的一份自洽包：

- `anim/pack.json` = **有效绑定**（角色包配置 **叠加**你在设置页做的改动），
  而不是角色包的原始文件 —— 你的改绑、加权、新加的场景都在里面；
- `anim/clips/` **只放被引用到的动作**（15 个状态场景 + 3 个事件场景的并集，含「待机随机池」）；
  素材按 **用户素材目录 → 角色包 clips → APK 内置** 的优先级解析；
- `anim/lines.json` 只保留**被包含动作**的台词；`character.json` / `memes/` / `persona.md` 有就带上；
- ★ **`appearance/` 也一起带上**（形象素材，见第五之一）—— 以前不带，于是"把包发给别人，
  对方拿到的角色没有脸"；现在导出提示里会如实写「已带上形象素材」或「这个角色没有自定义形象」；
- 解析不到素材的动作会**列出来提示**（不静默丢）；
- **内置角色也能导出**（按当前绑定导出不再是"只有 1 个动作的空包"）；
  确实一点都没改过时会先**提示**一次（不是拦死）。

> ★ 于是「导出 → 导入」是一个**往返一致**的操作：导入回来的角色，可播动作数与导出时收集到的
> 完全一致（这条由 `build/rt_test` 用真代码断言：真的写 zip、真的解压安装、真的重新装配计数）。

## 十一、多个角色：切换与删除

导入进来的角色不会覆盖内置角色 —— 它们是**并列**的，随时可切：

- 入口：设置页「形象与动作 → 动作系统 → **🎭 当前角色：… ›**」，点开是角色清单：
  `●` 是当前正在用的那个，`○` 是其他，内置角色会标注「（内置）」；
- **每个角色带自己的一整套**：动作套组（`anim/`）、台词、表情（`memes/`）、性格（`persona.md`），
  以及**你自己做的场景绑定与加进来的动作**（`filesDir/scenes/<角色 id>.json` 与
  `filesDir/scenes/<角色 id>/clips/`）。切角色 = 整套一起换，**互不串味**；
- 「🗑 删除角色…」可以删掉自己导入的角色：会把该角色的目录、它的绑定覆盖、
  用户加进去的动作、自定义动作菜单**一起清掉**（不留孤儿文件），角色包文件本身就随之删除；
- ★ **内置角色不能删**（删除清单里不会出现它）—— 它的素材在 APK 里，是所有"什么都没导入"时的兜底形象；
- ★ 删的正好是**当前正在用的**角色时，会自动回到内置角色；
- **记忆与 API Key 是全局的**（不随角色走），这是刻意的：换角色不等于换人设记忆。
