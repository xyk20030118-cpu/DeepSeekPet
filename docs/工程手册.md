> 真机实测 **prefill 12.7 → 25.2 tok/s（×2）**，但 **decode 基本没变（约 6.5 秒/字）**，
> 而且这台机器上 **GPU 最终没被用上**（驱动拒绝创建计算管线）⇒ 走了自动回退 CPU。
> 2）**轮次67**：★ **推翻了轮次66 的判断** —— "NDK 自带 glslc 太老"是**错的**：
> 用 NDK r29 的新 glslc 重编，**1119 个 SPIR-V 逐字节完全相同**，所以"换编译器"改不了任何东西。
> 改成**有上游依据**的修法（llama.cpp issue #28635 / PR #29165）：对 **Qualcomm（Adreno）**

> creation with `VK_ERROR_UNKNOWN`」，而 1 列就是单字解码），并留了 A/B 对照开关。
> ★ **这条有依据，但到本轮结束仍未在真机上确认治好**（如实标注）。

> （`off`/`auto`/`force`，默认强制）—— "开"的老语义是**失败静默回落 CPU**，
> 真机上它悄悄回落之后用户看到的却是 0.15 tok/s 而以为在用 GPU。
> 5）**轮次69（当前）**：按用户原话「**增加模型卸载功能，现在安装了之后模型无法更换其他的

> 轮次68 那个进程级"以前失败过就不再试"的标记会让一次 GPU 失败之后的**每一次加载**
> （换模型/重导都算）直接失败 ⇒ **整个删掉**；② GPU 加速**收回两态**：
> **开（默认，真的用 GPU、失败不回落）/ 关（纯 CPU）**，"自动静默回落"那一档去掉；
> ③ 新增 **「⏏ 卸载当前模型」**（放掉内存、**文件保留**）；
> ④ ★★★ **GPU 失败不再堵死退路**：卸载 / 更换 / 删除 / 导入 / 切回在线五条**都不受影响**
> （断言 + 反向破坏项钉着）。
> 3）补齐**证据链**：修好页面错误计数的解析 bug、新增**模型常驻内存**（`RssFile`）/ **被换出**
> （`VmSwap`）读数、加载后**主动预热 + 尝试 `mlock` 锁内存**；
> 设置页新增一行 **「🧠 内存提示：…」**（模型偏大或比可用内存还大时才出现，
> 把"模型 / 本机内存 / 可用内存"与**实测 6.5 秒/字**一起摆出来，并建议换 0.5B）。

> ③ **换源**：中国天气网两路都挂时自动改走 **wttr.in**（另一台主机，用拼音城市名）；
> ④ 时间戳改成 **5 分钟对齐**，不再每次随机。

## 一、30 秒上手

### A. 电脑上（推荐 —— 一条命令，无需安卓设备）

```sh
sh build/fetch_aapt2_pc.sh                  # 一次性：获取本机可用的 aapt2
sh build/build_pc.sh                        # 开发版
```

## 四、构建原理（想改代码必读）

### 阶段① aapt2 编译资源

```sh
LD_LIBRARY_PATH=build/toolchain/arm-libs \
  build/toolchain/arm-bin/aapt2 compile --dir res -o out/res.zip

LD_LIBRARY_PATH=build/toolchain/arm-libs \
  build/toolchain/arm-bin/aapt2 link \
    -o out/resbase.apk -I build/toolchain/android.jar \
    --manifest AndroidManifest.xml -R out/res.zip \
    --auto-add-overlay --java out/gen \
    --min-sdk-version 24 --target-sdk-version 34
```

> **`--auto-add-overlay` 不能省**，否则报
> `resource string/app_name does not override an existing resource`。

### 阶段② javac → dex → 组装 → 签名

```sh
# ① 编译（含阶段①生成的 R.java）
javac -source 8 -target 8 -bootclasspath build/toolchain/android.jar \
      -cp deps/sherpa-classes.jar:deps/kotlin-stdlib-1.9.0.jar \
      -d work/cls $(find src -name '*.java') out/gen/com/deepseek/pet/R.java

# ② 合并依赖（★ 关键，见坑 1）
cp -r work/cls/. work/all/
unzip -o deps/sherpa-classes.jar      -d work/all
unzip -o deps/kotlin-stdlib-1.9.0.jar -d work/all
rm -rf work/all/META-INF                       # ★ 必须删
find "$PWD/work/all" -name '*.class' > work/list.txt  # ★ 必须绝对路径

# ③ dex
java -cp build/toolchain/d8.jar com.android.tools.r8.D8 \
     --min-api 24 --lib build/toolchain/android.jar \
     --output work/dex @work/list.txt

# ④ 组装 + 签名
python3 build/assemble.py . out/resbase.apk work/dex/classes.dex work/unsigned.apk
java -jar build/toolchain/apksigner.jar sign \
     --ks debug.keystore --ks-pass pass:android --key-pass pass:android \
     --ks-key-alias androiddebugkey --out dist/out.apk work/unsigned.apk
```

预期规模：**373 源 class → 合并 1445 → dex 约 2.79 MB**
（method_ids ≈ 15.3k，无需 multidex）。

## 五、八个必踩的坑

### 坑 1（致命）DEX 必须合并 sherpa + kotlin-stdlib

只把项目自己的 class 交给 d8，会得到**能安装但一启动就崩**的 APK，浮窗提示：

```
离线识别引擎加载失败：NoClassDefFoundError: com/k2fsa/sherpa/onnx/OfflineModelConfig
```

原因：`com.k2fsa.sherpa.onnx.*` 是 Kotlin 写的（`deps/sherpa-classes.jar`），
还依赖 kotlin-stdlib。**必须**执行合并，且**必须删掉 `work/all/META-INF`**
（否则 kotlin-stdlib 的 multi-release 条目重复，d8 报错）。
class 列表**必须用绝对路径**，相对路径 `./com/...` 在不同 cwd 下会
`NoSuchFileException: ./kotlin/time/jdk8/...`。

### 坑 2 两个环境不能混用工具

- `aapt2` 是 bionic 程序 → 只能在 **Android Shell** 跑
- `javac`/`java` → 只能在 **Linux 工具环境**跑
- 在 Linux 环境里**不要把 `LD_LIBRARY_PATH` 指向 `arm-libs`**：
  里面的 `libz.so.1` 是 glibc 版，会污染环境导致
  `python3: Error relocating libz.so.1: __register_atfork: symbol not found`。
  跑阶段②前建议 `unset LD_LIBRARY_PATH`。

### 坑 3 `/tmp` 不跨环境共享

Android 与 Linux 工具环境的 `/tmp` **不是同一个**。
交换文件请用 `/data/local/tmp` 或 `/storage/emulated/0`。

### 坑 4 安装前必须拷出共享存储（SELinux）

```
Error: Can't open file: /storage/emulated/0/.../xxx.apk
avc: denied { read } for scontext=u:r:system_server:s0 ... tclass=file
```

`system_server` 无权读 fuse 共享存储。**先拷到 `/data/local/tmp/` 再 `pm install`。**

### 坑 5 修改清单后必须重跑阶段①

`build/out/resbase.apk` 里封着编译后的二进制清单。
改了 `AndroidManifest.xml` 却不重跑阶段①，改动**不会生效**。

另：用 `build/axml-tools/axml_set_version.py` 直接改已编译清单时，AXML
字符串池要求**新旧等长**（`5.6`→`5.7` 可以，`5.6`→`5.10` 不行）。
走 aapt2 重编译则无此限制 —— **推荐直接改明文清单重跑阶段①**。

### 坑 6 `.so` 必须页对齐

`lib/arm64-v8a/*.so` 在 APK 中必须 **4096 字节对齐**且 **stored 不压缩**，
否则安装后加载失败。`build/assemble.py` 用自研 ZIP writer 控制 extra 字段实现
（本机 `zipalign` 是 x86-64 ELF，跑不了）。

### 坑 7 中文源码字面量是 `\uXXXX` 转义

`MainActivity.java`、`FloatingService.java` 里中文多以 `\uXXXX` 形式保存。
用 Python 批量替换时**必须用 raw 字符串 / 显式转义写法**，
否则普通字符串会把 `\u8D5E` 当 unicode 转义处理，替换静默失效。
另外同一个文件里**可能混用**两种写法（部分原文、部分转义），
替换前先 `grep` 确认目标串的真实形态。

### 坑 8 改完源码要反向校验，别信「打包成功」

`assemble.py` 不会因为 dex 是旧的而报错。每次构建后应确认：

```sh
unzip -p dist/DeepSeekPet_v8.0_rebuilt.apk classes.dex | md5sum   # == work/dex/classes.dex
dumpsys package com.deepseek.pet | grep versionName              # == 清单里的 versionName
```

（阶段②脚本已内置 dex md5 比对，输出 `OK APK 内 dex 与编译产物一致` 才算可信。）

| 换动画素材 | `build/charpack_src/` + 默认角色包（`assets/webp/` 只剩 1 个兜底待机） |
| 换表情包 | `build/charpack_src/memes/` + `memes.json`（**随角色包分发**，APK 里没有表情） |
| 权限 / 版本号 / 组件 | `AndroidManifest.xml`（改完重跑阶段①） |
| 图标 | `res/mipmap-*/ic_launcher.png` |
| 气泡样式 | `res/drawable/bubble_*.xml` |

### 改版本号

直接编辑 `AndroidManifest.xml` 里的 `android:versionCode` / `android:versionName`
（**明文 XML，无等长限制**），然后重跑阶段①。关于页的版本号是运行时读
`PackageInfo`，无需改源码。

### 在线 API Key

`ApiClient.java` 不硬编码 Key，运行时由用户在设置页填入，存进 `Prefs`。
要内置默认值就改 `Prefs` 的默认常量 —— 但**别提交到公开仓库**。
