## 0. 装包、导模型（★ 这一步最容易白测）

1. 装**开发版**（★ 保留数据：你手机里的设置与那个模型都不会丢）。
   给你的 **`DeepSeekPet_v8.0_开发版.zip`** 解压出来，里面的 APK 就叫
   **`DeepSeekPet_v8.0_开发版.apk`**：
   ```
   adb install -r -d DeepSeekPet_v8.0_开发版.apk
   ```
   （★ 不想敲命令也行：把那个 APK 传到手机点它装 —— 同样**不要**先卸载旧版。）
2. ★★ **先导一个 0.5B（≈400 MB）来测**：`Qwen2.5-0.5B-Instruct Q4_K_M`
   （设置 →「陪伴 → 对话与人格 → 🤖 本地模型 → 📥 导入 .gguf 文件…」）。
   ★ 你原来那个 1.5B（≈1.0 GB）**先别拿来测速度**：**内存小的机器**（8 GB 那一档）
   上 1.5B 大概率被换页 / 压进 zram ⇒ 测出来的"慢"是**内存不够**，不是 GPU 不行。
   （★ 12 GB 的机器上 1.5B 是常驻的，实测 `RssFile` ≈ 模型体积 —— 见第 9 节。）
3. 设置 →「陪伴 → 对话与人格 → 🌐 服务商」→ 选「🤖 本地模型（手机本机跑，不联网）」。

## 1. ★★★ 什么都不用调：「自动」是默认

设置 →「陪伴 → 对话与人格 → 🤖 本地模型」，往下有一行：

```
⚡ GPU 加速：自动（按硬件决定） ›
```

点它弹出的是**三档**（标题「⚡ GPU 加速（选定后生效）」）：

| 档位 | 什么时候用 |
|---|---|
| **自动（默认 · 推荐）** | **平时就用它。** 运行时先看这台机器的 GPU 与可用内存，再算一次"放几层到 GPU"；放不下、或者驱动拒绝，就**自动**改用纯 CPU。★ 失败过一次也会自动降级一次，**不需要你去翻任何参数**。 |
| 开（手动 · 只走 GPU） | 只给要做 A/B 对照的人：强制用 GPU、失败**不回落**，把报错原样给你。 |
| 关（纯 CPU） | 明确不想用 GPU（更省电、更凉）。 |

★ 自动档**不是**"偷偷回落"：它会在面板、日志（`DSPLlm`）与自检报告里写明
「**自动计划=… / 自动降级=是**」——你随时能看见它到底决定了什么。

三档在设置页上分别显示为：`⚡ GPU 加速：自动（按硬件决定）` /
`⚡ GPU 加速：开（用 GPU）` / `⚡ GPU 加速：关（纯 CPU）`。

**万一你选了「开」却用不了**，手机上会弹一个框，两颗按钮是：
`改用「关」（纯 CPU）` / `保持开着（我知道了）`。点第一颗就当场切到纯 CPU。

（路径写法与 App 里一致：设置 → 陪伴 → 对话与人格 → 🤖 本地模型 → ⚡ GPU 加速）

## 2. ★ 怎么卸载 / 怎么换模型（你这次问的两件事）

都在**同一个面板**里：设置 →「陪伴 → 对话与人格 → 🤖 本地模型」。

| 想干什么 | 点哪一颗 | 会发生什么 |
|---|---|---|
| **卸载**（放开内存、**不删文件**） | `⏏ 卸载当前模型（<名字>，释放内存）…` | 内存里那几百 MB~1 GB 交还；面板上那一行变成「内存里**没有**载入模型（已卸载 / 还没载入）」。★ **文件保留，一个字节都不动** |
| **换模型** | `🔄 切换当前模型（已导入 N 个）…`（就是你说的"更换模型"） | 单选列表里**当前那个打勾**；选中后**先卸旧的、下次对话载新的**。日志：`换了当前模型：<旧> → <新>` + `本地模型已载入并常驻：<新>` |
| **再加一个 gguf** | `📥 导入 .gguf 文件…` | 多个 gguf **可以共存**；导进来的自动成为当前模型 |
| **彻底删掉** | `🗑 删除本地模型（<当前那个>）…` | 删的是**本机这一份**文件（你自己原来那个 .gguf 不动） |

★★★ **最要紧的一条**：开着 GPU 但用不了时，上面这四颗按钮**照样能用** ——
卸载、换模型、删除，以及「🌐 服务商」里切回在线服务商，**一条都不会被堵死**。
（上一版就是这里坏了：GPU 失败过一次之后，连"换一个模型"都直接报同一句
`开 GPU 失败…以前已经失败过` ⇒ 看起来就是"模型换不了"。这一版已经修掉。）

## 4. 盯这几行（右边就是"怎么读"）

| `DSPLlm` 里的日志 | 怎么读 |
|---|---|
| `★★ 后端设备：Vulkan0(Adreno …); CPU(CPU, …) ⇒ 开 GPU：认出 1 个 GPU 设备，按 999 层卸载（失败就不回落 CPU，会把原因报给你）` | 认出 GPU 设备了。★ **"999 层"是正常的**（请求全放 GPU，llama.cpp 自己夹到实际层数） |
| `llama_prepare_model_devices: using device Vulkan0 (Adreno (TM) 740) (unknown id) - … MiB free` | llama.cpp 真的准备用这块 GPU 了 |
| `load_tensors: offloaded 29/29 layers to GPU` | 层真的搬上去了（两个数字相等 = 全放上） |
| `compute pipeline creation failed for <着色器名>: vk::Device::createComputePipeline: ErrorUnknown` | ★★ **GPU 用不了的确切证据**（Adreno 驱动拒绝计算管线）。**"着色器名"是关键**，请连名字一起发回来 |
| `开 GPU 失败（已按你的设置不回落 CPU）：…原始错误：…` | 开着 GPU 的结果：**不回落**，把原因当面告诉你（手机同时会弹"改用关（纯 CPU）"的按钮） |
| `本地模型已载入并常驻：… / GPU 档位 on（开：真的用 GPU，失败不回落 CPU）` | 载入成功，而且**档位确实是 on（开）** |
| `已卸载内存里的本地模型：<名字> —— 内存已交还、★ 文件保留` | 点「⏏ 卸载当前模型」之后的证据（还有原生侧一行 `本地模型已卸载，内存已交还`） |
| `换了当前模型：<旧> → <新>` 紧跟着 `本地模型已载入并常驻：<新>` | ★★ **"换模型真的换成新的"** 就靠这两行连起来看 |
| `本地生成完成：prompt … tok / KV 复用命中 … tok / 新算 … tok / 出字 … tok / 首字 … ms / 共 … ms / … tok/s` | 这一句的总成绩（`首字` = 你等多久开始出字） |
| `分段读数：prefill … tok / … ms (… tok/s) · decode … tok / … ms (… tok/s, … ms/token)` | ★★ **最关键的两个数**：`prefill` = 首字速度；`decode` = 吐字速度（ms/token 越小越好） |
| `内存读数[模型加载完成]：本进程 RSS … MB（其中 模型文件 RssFile … MB / 匿名 RssAnon … MB / 已换出 VmSwap … MB） · 整机 MemAvailable … MB · zram Swap 已用 …/… MB` | `RssFile` = **模型真正常驻内存多少**。远小于模型体积 ⇒ 权重没常驻 |
| `页错误读数：prefill 段 minflt +… / majflt +… · decode 段 minflt +… / majflt +… · 模型文件常驻 RssFile …→… MB（模型本体 … MB）` | decode 段 `majflt` **每出一个字都在涨** ⇒ 每吐一个字都在从闪存重读权重 |

（进阶 A/B：想验证上一条 Adreno 补丁有没有用，
`adb shell setprop debug.dsp.adreno_subgroup 1` ⇒ `adb shell am force-stop com.deepseek.pet` ⇒ 再问一遍，
两次的 `compute pipeline creation failed for <名字>` 对比即可。）

## 5. 判定表

| 你看到的 | 结论 | 下一步 |
|---|---|---|
| 开 + **没有** `compute pipeline creation failed`，且 `decode` 的 ms/token 明显小于 6500 | ★ **GPU 真的用上了**（本轮想要的就是它） | 记下 `tok/s` 发回来 |
| 开 + `compute pipeline creation failed for <名字>`，或那句 `开 GPU 失败…` | ★★ **上一条 Adreno 补丁没治好** —— GPU 在这台机器上仍然不可用 | 把那行**整行**发回来；档位改成「关」就能继续用（纯 CPU） |
| 换 0.5B 后 `decode` 明显变快（哪怕还在 CPU 上） | ★ **"慢"的原因是模型太大 / 内存不够**，不是引擎慢 | 日常就用 0.5B；1.5B 别在 8 GB 机上指望速度 |
| `内存读数[…]` 里 `RssFile` 远小于模型体积（1.0 GB 的模型只常驻一两百 MB） | ★ **权重没常驻内存**，每个字都要重新捞一遍 | 关掉后台 App / 换 0.5B。★ 这一条 **GPU 也救不了**（GPU 和 CPU 取的是同一块内存） |

3. **用的是哪个模型**（文件名 + 多大，例如 `Qwen2.5-0.5B-Instruct-Q4_K_M.gguf`）。

★ 挂了也不用猜：**把那行日志原文发回来就行。**

★ 上面这三样其实都在这两份东西里，**发回来更省事**：
**第 7 节那份自检报告**（一键复制，里面有全部读数、含失败的着色器名）
或那份日志原文。**发一份就够，两份都发更好。**

## 7. 🧪 自检按钮怎么用（最省事的一条路）

设置 →「陪伴 → 对话与人格 → 🤖 本地模型」→ 点这一颗：

```
🧪 本地推理自检（跑一句，出一屏结果）
```

它会**先把内存里的模型放掉**（这样用的才是你**当前**的设置）、再载入、再跑一句固定短提示
（`你好！请用一句话介绍你自己。`，最多 24 个 token，贪心解码），然后弹出一屏结果。
结果框下面两颗按钮：**`📋 复制结果`** / 关闭 —— 点「复制结果」，粘到聊天框里发回来就行。
（★ 它不会问你要不要重载：自检的语义就是"按当前设置重新载入一次"。
★ 自检跑的时候可以点「取消」，它是在后台跑的，不会把界面卡住。）

那一屏里**每一行什么意思**：

| 那一行 | 怎么读 |
|---|---|
| `结果=成功 / 失败` | 就这一件事：这次到底跑起来没有 |
| `GPU 档位=` | 你选的那一档（`on` 开 / `off` 关） |
| `是否有 Vulkan GPU 设备=` 与 `后端设备清单=` | ★ **GPU 到底认没认出来**（名字就在括号里，例如 `Adreno (TM) 740`） |
| `请求卸载层=…` 与 `最终交给 llama.cpp 的层=…` | 请求全放 GPU 时是 999，llama.cpp 自己会夹到实际层数 |
| `prefill=… tok/s` | 首字速度（越大越好） |
| `decode=… tok/s, … ms/token` | ★★ **最要紧的那个数**（越小越好）。★ **读数按机型分段**：8 GB 那台老机（2210132C / Adreno 740）纯 CPU 是 ~6500 ms/token，而 `25091RP04C`（Adreno 830 / 12 GB）纯 CPU 就有 **22 ms/token** —— 两台机器的数**不许互相套** |
| `首字（TTFT）=… ms` | 从按下到第一个字出来 |
| `内存[生成前]` 那一行 | `RssFile` = 模型真正常驻内存多少；`VmSwap` = 被换出去多少；`MemAvailable` = 整机还剩多少 |
| `最近的后端警告/错误=` | ★★ 里面有 `compute pipeline creation failed for <名字>` 的话，**那个名字最要紧** |
| `原始错误=` | 失败时的原始错误串（成功时是 `（无）`） |

★★ **报告最上面那两行就是"我该怎么办"**（`【结论】` 与 `【下一步】`）——
真机实测之后，凡是"纯 CPU 反而更快"的机器，那里会直接写出
**`★ 建议这台机器把「⚡ GPU 加速」设成「关」（纯 CPU）`**（并附上实测读数与
"GPU 那条路已经被驱动拒绝过"这句原文）。**不用自己从 tok/s 去推。**

★ 报告里**不会再出现 `-1 ms`** 这种读不出来的东西：**没测到的项会写
`未测到（这一步没跑到）`**，而且那一行**不会再带 `0.00 tok/s`**
（`0.00 tok/s` 会被读成"跑了但极慢"，而事实是**根本没跑**）。

## 8. 🎛 GPU 参数怎么 A/B（一次只改一个）

同一个面板里再往下还有一行：

```
🎛 本地推理调优（进阶 · A/B 用）：全是默认值 ›
```

点进去是**九个小旋钮**，每一个都有默认值 ——
**什么都不动 = 和上一版完全一样**（这一点很重要：不玩 A/B 的人零影响）。
★★ **做 A/B 时先把档位切到「开（手动 · 只走 GPU）」** —— 自动档会替你判断
（在已知坏机型上它直接选纯 CPU），那样改旋钮**看不出差别**，你会误以为旋钮没用。
想找出"哪个参数能让 GPU 跑起来 / 让速度变快"，就照这个傻瓜流程：

1. 先点一次 **`🧪 本地推理自检`**，把 `结果=` 与 `decode=` 两行记下来（这是**基线**）；
2. 回「🎛 本地推理调优」，**只改一个**旋钮（推荐顺序见下表）；
3. 按那一项"什么时候生效"去做（★ 有五项要**完全退出 App 再打开**：划掉最近任务再打开）；
4. 再点一次 `🧪 本地推理自检`，比 `结果=` 和 `decode=` 两行；
5. 好了就留着；不好就点 `↩ 全部恢复默认（试乱了点这个）`，换下一个旋钮。

| 旋钮 | 推荐顺序 | 什么时候生效 |
|---|---|---|
| `Adreno 的归约方式` | 第 1 个试：`强制 subgroup 归约（对照组）`，第 2 个试：`第三档：子组归约 · 不用共享内存`（轮次73 新增） | ★ 完全退出 App 再打开 |
| `Vulkan 量化矩阵乘（MMVQ）` | 第 2 个试：`关掉 MMVQ`（★ 最可能绕开那个被拒的着色器） | ★ 完全退出 App 再打开 |
| `Vulkan 半精度（fp16）` | 第 3 个试：`关掉 fp16（全部走 f32）`（轮次73 新增） | ★ 完全退出 App 再打开 |
| `Vulkan 算子融合` / `Vulkan 异步提交` | 第 4 个试：`关` | ★ 完全退出 App 再打开 |
| `flash attention` | `强制关` / `强制开` | 下一次载入 |
| `n_ubatch（物理批大小）` | `128` / `256` / `1024` | 下一次载入 |
| `权重锁进内存（mlock）` | `关` / `尝试`（默认） | 下一次载入 |
| `权重载入方式` | `不用 mmap（对照）` | 下一次载入 |

★★ 每一次载入都会把这一套参数**原样打进日志**（`DSPLlm`），自检报告里也有同样两行：

```
本次调优（与本轮默认不同的项）：flash=off, ubatch=1024 ｜ 完整串：adreno=auto;flash=off;ubatch=1024;…
生效参数：flash attention=off（强制关） / n_ubatch=1024 / 载入方式=mmap / 权重锁内存=尝试
```

★ 判读：两次自检的**完整串**不一样、而结论一样 ⇒ 那个旋钮没用；
结论变了（例如从"驱动拒绝计算管线"变成"成功"）⇒ **就是它**，把它留在那儿。

## 9. ★★★ 真机实测结论（2026-10-16 · 骁龙 8 Elite / Adreno 830）

这一节是**实测**，不是推测：工程第一次把手机连上电脑，把第 8 节那八个旋钮逐个跑了一遍。
**你这台手机**（`25091RP04C` / 骁龙 8 Elite / **Adreno (TM) 830** / 12 GB / Android 16）：

| 试过的组合 | 结果 |
|---|---|
| **GPU 开**（默认档，走 Adreno 回退补丁） | ❌ **失败**：`compute pipeline creation failed for mul_mat_vec_q4_k_f32_f32`（驱动拒绝计算管线） |
| `Adreno 的归约方式` → 「强制 subgroup 归约」（对照组） | ❌ 一样失败 ⇒ **那条补丁在你这台机器上没用** |
| `Vulkan 量化矩阵乘（MMVQ）` → 关掉 | ❌ 一样失败 |
| MMVQ 强制 / `算子融合` 关 / `异步提交` 关（含组合，共 6 组） | ❌ **全都一样失败**，报错**逐字相同** |
| **GPU 关（纯 CPU）** | ✅ **成功**：首字 **76 ms**、prefill **109.5 tok/s**、decode **22 ms/token（44.75 tok/s）** |

★ 收尾时**又照同一套协议复现了一遍**：decode **24 tok / 535 ms = 44.84 tok/s（22 ms/token）**
⇒ 这个量级**可重复**（不是一次侥幸）。

★ 结论三条：

1. **这台手机的 Vulkan GPU 用不了** —— 设备认得出来、层也真的卸载上去了
   （日志里是 `load_tensors: offloaded 29/29 layers to GPU`），但驱动在**第一次建计算管线**时拒绝。
   **换哪个旋钮都救不了**（六个组合全试过），别再花时间猜参数。
2. **"慢得离谱"不是内存问题**：模型 1.0 GB，`RssFile` 实测 **1214 MB**（= 权重**常驻内存**）、
   被换出只有 23 MB。手册里那个"**6.5 秒/字 / 163 MB/s**"是**另一台 8 GB 手机**上的读数，
   **不适用你这台**。
3. ⇒ **在你这台手机上，最佳设置就是「⚡ GPU 加速 → 关（纯 CPU）」**：
   22 ms/token 已经很快（比那台 8 GB 机的"6.5 秒/字"快约 300 倍）。
   ★ 想自己切：设置 → 陪伴 → 对话与人格 → 🤖 本地模型 → ⚡ GPU 加速 → 「关（纯 CPU）」。

## 10. ★★★ 轮次73 补测：唯一没试过的那条着色器也失败了（2026-10-17 · 同一台 Adreno 830）

第 8 节那九档里，`Adreno 的归约方式` 其实有**三条**着色器变体（共享内存 / subgroup / hybrid）。
轮次72 只试了前两条 ⇒ 这一轮把**第三条**也接出来试了（上游在 Qualcomm 上永远选不到它，
本工程加了一条本地补丁才够得着）：

| 档位 | 结果 | 现场证据 |
|---|---|---|
| `Adreno 的归约方式` → 「第三档：子组归约 · 不用共享内存」 | ❌ **一样失败** | 日志里**真的**选到了第三档：`Adreno HYBRID 检查：use_subgroups=1 … ⇒ use_subgroups16=1` + `Adreno HYBRID 生效：dmmv_wg=LARGE`；仍然 `compute pipeline creation failed for mul_mat_vec_q4_k_f32_f32` |
| `Vulkan 半精度（fp16）` → `关掉 fp16（全部走 f32）` | ❌ **一样失败** | `Vulkan 半精度（fp16）＝关（GGML_VK_DISABLE_F16=1）`，报错**逐字相同** |

★ 结论：**在 Adreno 830 上"换一条着色器变体"这条路已经走完** —— 三条归约全被同一个驱动拒绝，
fp16 也救不了。**别再猜参数**，就用「⚡ GPU 加速 → 关（纯 CPU）」（22 ms/token）。
★ 仍然**没试过**的是 `flash` / `n_ubatch` / `mlock` / `载入方式` 这四个**载入级**旋钮在 GPU 路上 ——
它们改的是内存与批大小，**不改**"用哪条 SPIR-V"，所以机制上救不了建管线失败（这是推断，不是实测）。

## 11. ★★★ 「自动」到底怎么自动（轮次74 · 你提的核心思路）

顺序是固定的三步，**每一步都不需要你操作**：

1. **看硬件**（每次载入前，后台线程）：枚举 ggml 的后端设备 → 有没有 Vulkan GPU、
   设备名（例如 `Adreno (TM) 830`）、显存/内存；再读 GGUF 头里的 `<arch>.block_count` 拿**层数**。
2. **算层数**（`GpuPlan`，纯函数）：`每层大小 = 模型体积 / 层数`；
   `预算 = 可用内存 × 55%（上限 3072 MB）`；`n_gpu_layers = 预算 / 每层大小`。
   放得下全部层 ⇒ 全放；放得下 1/3 以上 ⇒ 部分放；再少 ⇒ 直接纯 CPU（部分卸载往往更慢）。
   **已知坏机型（Adreno 830）⇒ 直接纯 CPU**，不再白试一次。
3. **自动降级**：计划要用 GPU、但载入或第一次生成因为 GPU 原因失败
   （`compute pipeline creation failed` / `vk::…`）⇒ **自动卸掉、按纯 CPU 重载重跑一次**，
   并把原因记下来（面板 + 日志 + 自检报告里的 `自动降级=是`）。

自检报告里现在多了两行，就是这套决策的现场证据：

```
自动计划=cpu-known-bad ｜ 层数=0 ｜ 预算=4390 MB ｜ 每层≈37 MB ｜ 自动降级=否
硬件=Adreno (TM) 830 ｜ Vulkan=1 ｜ 驱动=unknown ｜ 可用内存=7981 MB ｜ 模型=28 层
```

★ 判读：`自动计划=` 是档位（`cpu-no-vulkan` / `cpu-known-bad` / `cpu-budget` /
`gpu-full` / `gpu-partial` / `cpu-fallback`）；`自动降级=是` = 试过 GPU、失败了、已换 CPU。
★ 已知坏机型名单只有**实测过的那一个**（Adreno 830）；别的机型会**先试** GPU，失败再降级。
