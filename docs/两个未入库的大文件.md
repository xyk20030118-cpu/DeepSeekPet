# 两个没有进仓库的大文件（不是漏了，是带宽限制）

发布时隧道上行只有约 20 KB/s，单个请求超过约 1.3 MB 就会在 77 秒左右被网关截断
（GitHub 回 `401 Bad credentials`，实际是请求体没传完）。下面两个文件因此没有入库：

| 文件 | 大小 | 为什么需要 | 怎么拿 |
|---|---|---|---|
| `deps/kotlin-stdlib-1.9.0.jar` | 1.6 MB | 构建期 javac 的 classpath 依赖（Kotlin stdlib，运行时也要打进 dex） | Maven Central：`https://repo1.maven.org/maven2/org/jetbrains/kotlin/kotlin-stdlib/1.9.0/kotlin-stdlib-1.9.0.jar` |
| `assets/webp/待机呼吸休闲.webp` | 2.7 MB | 桌宠的兜底待机动画（角色包缺失时用它） | Release 里的 `DeepSeekPet_默认角色包_v8.0.zip`，或 `DeepSeekPet_v8.0_项目移植包.zip` 的同名路径 |

## 放回去

按上表的原始路径放回工程根即可，构建脚本按固定路径找它们：

```
deps/kotlin-stdlib-1.9.0.jar
assets/webp/待机呼吸休闲.webp
```

## 顺带说明

- 其余 467 个文件（源码 / 资源 / 文档 / 断言脚本 / 5 个依赖 jar / 角色包素材 28 个文件）都在仓库里。
- `deps/` 下另外 5 个 jar（sherpa-classes、shizuku-*）体积都小于 1 MB，已正常入库。
- 只读源码看逻辑完全不受影响；要出完整 APK 才需要补齐这两个文件。
