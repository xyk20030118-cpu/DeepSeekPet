# DeepSeek桌宠 · 电脑端开发指南

> 目标读者：**在电脑上接手本项目的开发者 / AI Agent**。
> 读完本文，你应当能在这台电脑上**独立完成**：改代码 → 构建 APK → 验证 → 出交付包，
> 全程**不需要安卓设备**。

---

## 0. 三十秒速览

```sh
# 一次性准备（只做一次）
sh build/fetch_aapt2_pc.sh

# 开发版构建
sh build/build_pc.sh

# 正式版构建（自动生成正式版工程 → 构建 → 独立签名）
DSP_VARIANT=release sh build/build_pc.sh

# 装上手机
adb install -r -d dist/DeepSeekPet_v8.0_rebuilt.apk
```

需要：**JDK 8+**、**Python 3**、**unzip**。就这些。

## 1. 工程是什么

一个**纯手写构建**的 Android 应用（不依赖 Gradle / Android Studio）。

| 项 | 值 |
|---|---|
| 开发版包名 | `com.deepseek.pet` |
| 正式版包名 | `com.doropet.release` |
| versionName | 8.0 |
| versionCode | 开发版 80 / 正式版 1080 |
| 语言 | Java 8（`-source 8 -target 8`） |
| minSdk / targetSdk | 24 / 34 |
| 架构 | 仅 arm64-v8a |
| 依赖 | sherpa-onnx（离线语音）+ kotlin-stdlib 1.9.0 |
| 体积 | 约 596 MB（含 228 MB 离线语音模型） |

## 2. 环境准备

### 2.1 必需

| 工具 | 版本 | 说明 |
|---|---|---|
| JDK | 8 或更高 | 需要 `javac` 与 `java` |
| Python 3 | 3.x | 构建脚本、组装器 |
| unzip | 任意 | 解包 jar / APK |

Windows 用户：**用 Git Bash / MSYS2 运行 shell 脚本**（不要用 cmd 或 PowerShell 跑 `.sh`）。

### 2.2 aapt2（唯一需要单独准备的）

资源编译用的 `aapt2` 是平台相关的原生程序：

- 工程内 `build/toolchain/arm-bin/aapt2` 是 **Android aarch64** 程序
  （ELF `e_machine=0xB7`，`PT_INTERP=/system/bin/linker64`），**电脑上无法运行**；
- 电脑需要自己的一份：

```sh
sh build/fetch_aapt2_pc.sh
```

脚本会自动判断平台（Linux / macOS / Windows-Git-Bash）并从 Google Maven 下载对应
`aapt2`（默认版本 `8.13.2-14304508`）解到 `build/toolchain-pc/`。

> **本移植包已内置 Linux x86-64 版 aapt2** 于 `build/toolchain-pc/aapt2`，
> 因此 **Linux / WSL 用户开箱即用**，无需联网。
> macOS 与 Windows 用户请跑一次 `fetch_aapt2_pc.sh`。
> Apple Silicon 上该二进制是 x86-64，需 Rosetta 2：
> `softwareupdate --install-rosetta --agree-to-license`。

### 2.3 不需要的东西

以下**都不需要**：Android Studio、Gradle、Android SDK、aapt2 以外的 build-tools、NDK。
`android.jar` / `d8.jar` / `apksigner.jar` 已随工程提供，且都是**纯 Java 字节码，跨平台通用**。

## 3. 构建

### 3.1 开发版

```sh
sh build/build_pc.sh
# 产物： dist/DeepSeekPet_v8.0_rebuilt.apk
```

### 3.2 正式版

```sh
DSP_VARIANT=release sh build/build_pc.sh
# 产物（在正式版工程目录内）： ../DeepSeekPet_Release/dist/DeepSeekPet_v8.0_release.apk
```

这个命令会自动：

1. 调用 `build/make_variant.py` 从**当前开发版工程**生成正式版工程副本
   （默认输出到 `../DeepSeekPet_Release`，可用 `DSP_RELEASE_DIR` 指定）；
2. 完成包名 / 版本号 / 应用名 / 赞赏码的转换；
3. 用 `release.keystore` 签名。

> ★ **重要**：正式版工程是**生成物，不要手改**。改了会在下次生成时被覆盖。
> 要改正式版行为，一律改开发版源码，然后重新生成。
>
> ★ **正式版永远是当前代码**：`build_pc.sh` 每次都会重新生成正式版工程，
> 因此电脑端不存在「正式版工程落后于开发版」的问题
> （设备端两阶段脚本是按目录选变体的，需要你自己记得重跑 `make_variant.py`）。

### 3.3 构建流水线做了什么

```
res/ ──aapt2 compile──► res.zip ──aapt2 link──► resbase.apk + R.java
                                                   │
src/*.java + R.java ──javac──► 373 class ──┐        │
                                            │        │
deps/sherpa-classes.jar ──────────┐         │        │
deps/kotlin-stdlib-1.9.0.jar ─────┤ 合并（删 META-INF）
                                  └► 1445 class ──d8──► classes.dex
                                                          │
resbase.apk + assets/ + model/ + lib/*.so + classes.dex ──┴──► assemble.py ──► unsigned.apk
                                                                                   │
                                                                    apksigner ──► dist/*.apk
```

关键点（**踩过坑，别改动**）：

- dex **必须**合并 `sherpa-classes.jar` + `kotlin-stdlib-1.9.0.jar`，
  并**删掉 `META-INF`**，否则安装成功但一启动就 `NoClassDefFoundError`；
- `aapt2 link` **必须**带 `--auto-add-overlay`；
- `assemble.py` 是**自研 ZIP 写入器**（为精确控制 extra 字段做 4096 页对齐，
  因为 `zipalign` 是 x86-64 程序，在 arm64 设备上跑不了）。
  它自己负责：`resources.arsc` 首个且 stored、`.so` stored + 4096 对齐、
  `.onnx/.txt` stored、其余 deflate，以及**中文素材名的 cp437→UTF-8 还原**。

### 3.4 一致性

电脑端与设备端构建**结果一致**。实测（本工程 6.1）：

| 变体 | 设备端 dex md5 | 电脑端 dex md5 | 结论 |
|---|---|---|---|
| 开发版 | `5425520f9c579b02fd807d3305e2537c` | 同左 | **逐字节相同** |
| 正式版 | `d8361279bccd827ebc5e2b6654529081` | 同左 | **逐字节相同** |

（`javac -source/-target 8` + 同一份 `d8.jar`，因此 dex 确定性一致。）

## 4. 安装与验证

```sh
adb install -r -d dist/DeepSeekPet_v8.0_rebuilt.apk
adb shell am start -n com.deepseek.pet/.MainActivity
adb logcat -d | grep -E "FATAL EXCEPTION"
```

两版包名不同，**可同时安装**，互不覆盖、各自保留数据。

### 构建脚本自带的校验

`build_pc.sh` 每次都会自动做：

- **反向校验**：解出 APK 内 `classes.dex`，与编译产物比 md5，不一致就**报错退出**；
- **产物核验**：打印清单里的 `versionCode/versionName`、签名证书 DN 与 SHA-256、dex 内包名路径；
- 正式版额外确认 `reward_qr.png` 已打入。

### 验证文案是否真进了 APK

```sh
unzip -p dist/DeepSeekPet_v8.0_rebuilt.apk assets/第三方许可声明.md | wc -c    # 应为 6853
python3 - <<'EOF'
import zipfile; z=zipfile.ZipFile("dist/DeepSeekPet_v8.0_rebuilt.apk")
print(len(z.read("assets/第三方许可声明.md")), z.read("assets/第三方许可声明.md").count(b"ex-skill"))
EOF
```

## 5. 开发须知（改代码前必读）

### 5.1 人格系统

- **唯一入口**：`Prefs.getPersona(ctx)` —— 全项目都从这里取人格字符串，
  改人设相关逻辑**务必**先看这里；
- 存储：SharedPreferences `chat_persona`，JSON 数组 `[{name,content}]`，
  另有 `chat_preset_index`；
- persona 是**纯文本字符串**，作为第一条 system 消息注入，顺序为
  `persona → TimeContext → facts → antiRepeat → history`；
- 对话限制：`max_tokens=800`（记忆整理 200）。

### 5.2 可离线单测的纯逻辑类（无需设备）

这几个类**不依赖 Android**，可以直接在本机 `javac` + `java` 单测：

| 类 | 职责 |
|---|---|
| `ReplySplitter` | 回复分段（连发消息表现力） |
| `SkillImporter`（剥离 android import 后） | ex-skill / markdown 导入 |
| `PersonaDistiller` | 人格蒸馏 |

> 例：单测 `ReplySplitter` 时，把源文件拷到临时目录、去掉 `package` 行与 android import，
> 补一个 `org.json.JSONObject` stub 即可编过（仅 `SkillImporter` 需要 stub）。

### 5.3 关键常量与默认值

| 项 | 值 | 位置 |
|---|---|---|
| `MIN_SEG_CHARS` | 2（**不能是 3**，否则「哦。」会被并掉） | ReplySplitter |
| `FALLBACK_MIN` | 50 | ReplySplitter |
| `MAX_CHARS`（导入上限） | 40000 | SkillImporter |
| `splitMax` 默认 | 3（范围 1–5） | Prefs |
| `splitDelayMs` 默认 | 900（范围 300–3000） | Prefs |
| `SPLIT_BUBBLE_MS` | 6000 | FloatingService |

### 5.4 泛化陷阱

- `SkillImporter` 判定「是不是人格文件」的依据是**内容**（含 `# ` 一级标题，
  或含 layer / persona / 共同记忆 / memories），**不看来源**。
  因此**任意带一级标题的 markdown 都会被当人格吞掉**——这是已知行为，不是 bug，
  但改导入 UI 文案时要留意；
- 「共同记忆」是**刻意并入 persona 文本**的，不写进 facts
  （facts 上限仅 6 行 / 400 字符，会截掉大半）。

### 5.5 中文文件名

`assemble.py` 有 `fixname()` 做 `cp437 → UTF-8` 还原，**中文素材名必需**。
如果新增中文名的 asset，构建后请确认 APK 内能被正常读出（见 §4）。

## 6. 出交付包

移植包/交付包若需重新打包，**在电脑上做**（安卓侧无 `zip` 命令）：

```sh
zip -r -0 DeepSeekPet_v8.0_开发版.zip dist/DeepSeekPet_v8.0_rebuilt.apk 开发版交付说明.md 开发版README.md
zip -r -0 DeepSeekPet_v8.0_正式版.zip dist/DeepSeekPet_v8.0_release.apk ...
zip -r -6 DeepSeekPet_v8.0_项目移植包.zip DeepSeekPet_v8.0_完整工程/
```

- 大 APK 用 `-0`（免压缩，否则打包极慢且几乎不省体积）；
- 移植包用 `-6`（源码/文档压缩收益明显）。

## 7. 与设备端脚本的关系

| | 设备端 | 电脑端 |
|---|---|---|
| 阶段① 资源编译 | `1_compile_android.sh`（需安卓 aapt2） | 内置进 `build_pc.sh` |
| 阶段② Java/dex/签名 | `2_build_linux.sh`（需 JVM） | 内置进 `build_pc.sh` |
| aapt2 | `toolchain/arm-bin/aapt2` | `toolchain-pc/aapt2` |
| 正式版工程 | 手动 `make_variant.py` | **自动生成** |
| 命令 | 两条、两个环境 | **一条** |

设备端脚本**保留可用**（在手机上原地开发时仍会用到），但电脑端优先用 `build_pc.sh`。

## 8. 快速排错

| 症状 | 原因 / 处理 |
|---|---|
| `!! 未找到电脑可用的 aapt2` | 跑 `sh build/fetch_aapt2_pc.sh` |
| aapt2 报 `cannot execute binary file` | 拿错平台了；重跑 fetch 脚本 |
| `syntax error: unexpected ")"`（跑 aapt2 时） | 在执行**安卓版** aapt2；换 PC 版 |
| javac `NoClassDefFoundError` 仅运行时 | 少合并了依赖 jar，或没删 `META-INF` |
| 安装成功但一启动就崩 | 同上；检查 dex 是否含 sherpa/kotlin 类 |
| 中文 asset 读不到 | 确认走的是 `assemble.py` 组装，而非普通 `zip` |
| 正式版显示开发版版本号 | 用 `build_pc.sh`（会自动生成正式版工程），别手动指定 keystore |
| Apple Silicon 上 aapt2 不跑 | 装 Rosetta 2 |
